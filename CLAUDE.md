This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

RELXILL is an astrophysics X-ray relativistic reflection model for analyzing accretion disk reflection around black holes and neutron stars. It is used as a *local model* in X-ray spectral fitting software (ISIS, Xspec, Sherpa). The code is a mix of C (older physics routines) and C++ (newer components, model framework).

## Build Commands

The build system is CMake invoked through a top-level Makefile. HEASoft must be installed and sourced.

```bash
make install          # Compile source files and install to bin/ and model/
make model            # Full build: compile + create tarball + link with Xspec → build/
make model-stable     # Same, but only stable (public) models
make dist-clean       # Remove all build artifacts
```

**Build steps performed by `make model`:**
1. Merges `src/modelfiles/lmodel_relxill_public.dat` + `lmodel_relxill_devel.dat` → `src/lmodel_relxill.dat`
2. Auto-generates `xspec_wrapper_lmodels.cpp/h` from the lmodel.dat
3. Compiles everything into `bin/` (library + `test_sta` binary)
4. Creates tarball and compiles as Xspec local model in `build/`

New `.c/.cpp/.h` files must be added to `SOURCE_FILES` in `src/CMakeLists.txt`.

## Testing

```bash
make test             # Run unit tests + all e2e tests (stable + dev models)
make test-unit        # Unit tests only: runs bin/tests (requires make install first)
make test-stable      # Build stable model then run stable e2e tests
bin/tests             # Run unit test binary directly (after make install)
bin/tests "[tag]"     # Run specific Catch2 test by tag or name
cd test && make test  # Run e2e tests only (requires ISIS)
make test-refdata     # Compare output against reference FITS files in test/refdata/
```

Unit tests use [Catch2](https://github.com/catchorg/Catch2) and are in `test/unit/`. Each `.cpp` file there is compiled into `bin/tests`. New test files must be added to `test/CMakeLists.txt`.

E2e tests are ISIS scripts in `test/e2e/` and require the model to be compiled and loaded. Reference data lives in `test/refdata/` and is generated by `test/e2e/create_reference_data.sl`.

**Required environment variable** for tests: `RELXILL_TABLE_PATH` must point to the reflection table FITS files.

## Architecture

### Model Definition Flow

Models are defined bottom-up:
1. **`src/modelfiles/lmodel_relxill_public.dat`** / **`lmodel_relxill_devel.dat`** — Xspec-format model descriptors (parameters, units, limits). Public = stable release; devel = development only.
2. **`src/ModelInfo.h`** — `ModelName` enum identifying each model uniquely.
3. **`src/common.h`** — `MOD_TYPE_*` integer constants and the `relParam` struct holding all model parameters.
4. **`src/ModelDefinition.h/.cpp`** — `XPar` class (parameter enum), `get_rel_params()` (defaults), `convertModelType()` (ModelName → int).
5. **`src/ModelDatabase.h`** — `ModelDatabase` class: registers each model's type (Convolution/Relxill/Line), irradiation geometry (LampPost/PowerLaw/…), and primary spectral shape (CutoffPL/Nthcomp/Blackbody).
6. **`src/LocalModel.cpp`** — C++ Xspec wrapper; dispatches parameter structs to the correct physics kernel.
7. **`src/xspec_wrapper_lmodels.cpp/h`** — Auto-generated; provides C-linkage entry points that Xspec calls.

### Physics Components

| Component | Files | Role |
|-----------|-------|------|
| Core relativistic profile | `Relbase.cpp/h`, `Relphysics.cpp/h` | Disk geometry, Doppler/beaming, relativistic line profiles |
| Lamp post geometry | `Rellp.cpp/h` | Primary source on symmetry axis, photon trajectories |
| Extended corona | `Rellp_Extended.cpp/h` | Ring-like corona model |
| Ionized reflection | `Xillspec.cpp/h`, `Xilltable_handling.cpp/h` | Reads xillver tables, computes reflected spectrum |
| Return radiation (BB) | `Relreturn_BlackBody.cpp/h` | Disk photons returning to disk (blackbody) |
| Return radiation (corona) | `Relreturn_Corona.cpp/h`, `Relreturn_Table.cpp/h` | Coronal return radiation |
| Ionization gradient | `IonGradient.cpp/h` | Radial ionization variation along disk |
| Primary source continuum | `PrimarySource.cpp/h` | Cutoff power-law, Nthcomp, blackbody shapes |
| Caching | `Relcache.cpp/h` | Parameter change detection; avoid redundant recomputation |
| Table I/O | `reltable.c/h`, `relutility.c/h` | Read/interpolate relativistic reflection FITS tables |
| JedSad model | `JedSad.cpp/h` | Alternative jet-disk-SAD reflection geometry |
| Main evaluation kernel | `Relxill.cpp/h` | Orchestrates all components; top-level `xspec_*` calls land here |

### Caching

Performance is critical (called per fitting iteration). `Relcache.cpp` detects which parameters changed and skips recomputation of expensive steps. **When adding new parameters**, they must be added to `comp_sys_param`, `did_rel_param_change`, `set_cached_rel_param`, and `set_cached_xill_param` in `Relcache.cpp`, otherwise the model will not update correctly within a fitting session.

### Adding a New Model — Checklist

1. Add entry to `lmodel_relxill_public.dat` or `lmodel_relxill_devel.dat`
2. Add new parameters to `XPar` (ModelDefinition.h), `relParam` (common.h), and defaults in `get_rel_params()` (ModelDefinition.cpp)
3. Add model name to `ModelName` enum (ModelInfo.h)
4. Add `MOD_TYPE_*` constant to `common.h`; wire it in `convertModelType()` (ModelDefinition.cpp)
5. Register model in `ModelDatabase` (ModelDatabase.h)
6. Add new parameter cache checks in `Relcache.cpp`
